# Erdos 实验方案：反馈能否改善神经定价模型的测试？

本项目研究 **LLM 如何利用实验反馈选择测试区域**。神经网络是被测试的期权定价器，LLM 是测试方案的提出者，Python 是独立执行与评分工具。我们不测试股票涨跌预测，也不把定价近似精度当作交易收益。

`runs/demo` 是已经用于探索问题的开发样例。此前单次助手 pilot 有助于发现流程和指标的问题，但不进入新的正式比较。新研究的配置以 `configs/erdos_v2.json` 为准，运行结果以 `studies/erdos_v2` 中保存的实际记录为准。

## 1. 研究问题与可否证的假设

**主要问题：** 对同一个冻结的神经定价器，在相同数值评估预算下，接收新反馈的 LLM，是否比同一个不接收新反馈的 LLM 找到更大的绝对价格误差？

**次要问题：** 它是否优于 Sobol、固定金融压力测试及合理配置的差分进化？发现极端错误和覆盖更多失败参数区域之间是否存在取舍？

反馈组没有优势也是有效结果。只有在与无反馈组的配对比较中表现更好，才能把改善与“获得新实验结果”联系起来；只比随机采样好，不能证明反馈有效。

## 2. 数据、模型和独立性

使用无分红欧式看涨期权，固定 `K=100`、连续复利年利率 `r=0.02`。输入为 `m=S/K`、剩余期限 `T` 和波动率 `sigma`，输出为 `C/K`。实验域为：

| 参数 | 范围 |
|---|---|
| `m` | 0.5–1.5 |
| `T`，年 | 1/365–1 |
| `sigma` | 0.05–0.80 |

主数据由 Black–Scholes 公式生成，22 条 QuantLib 公开样例用于独立检查参考计算器，不用于训练。来源、许可和局限见 [DATA_SOURCES.md](DATA_SOURCES.md)。这些是理论价格，不是真实市场报价。

三个新的模型实例使用相同架构和训练规则，但各自生成数据并训练：

| 模型实例 | 训练随机种子 | 数据基础种子 |
|---|---:|---:|
| A | 17 | 20261001 |
| B | 29 | 20261011 |
| C | 43 | 20261021 |

每个实例包含训练 32,768 条、验证 4,096 条、全域测试 8,192 条、压力诊断 8,192 条。各划分独立生成；压力诊断强调短期限和平值区域。网络为 `3 → 64 → 64 → 1`、SiLU，最多训练 200 个 epoch，按验证误差选择 checkpoint，允许既定的提前停止。

数据的用途必须分开：

- **训练集：** 更新权重。
- **验证集：** 选择 checkpoint；不用于比较搜索方法。
- **测试集和压力诊断集：** 给冻结网络提供独立的价格及 delta 诊断，不提供给 agent。
- **搜索点：** 各方法在预算内提出并评估；用于衡量搜索效果，不用来估计平均市场误差。

三个实例同时改变数据和训练种子，测试的是结论对不同训练实例的稳定性，不能把差异单独归因于初始化。搜索期间不得继续训练或修补这些网络；若后续进行修复，应另开实验。

## 3. 六种方法和统一预算

每个模型使用搜索种子 `701、702、703`，形成 **3 个模型 × 3 个搜索种子 = 9 组配对设置**。每组中所有方法获得相同的 128 个全域 Sobol 初始点，随后各有 896 个评估点，总预算严格为 1,024。

| 方法 | 初始点后的决策规则 | 主要作用 |
|---|---|---|
| Random | 全域均匀随机采样 | 普通覆盖基线 |
| Sobol | 继续低差异覆盖 | 更均匀的空间覆盖基线 |
| Financial stress | 按预先锁定的七个金融压力区域，每区 128 点 | 检查金融先验是否已能解释优势 |
| Differential evolution | 数值优化绝对价格误差 | 不依赖语言模型的自适应搜索基线 |
| LLM without feedback | 七次提出区域，每次 128 点；只看初始结果和此前提议 | 控制 LLM 已有知识与顺序规划能力 |
| LLM with feedback | 同样七次提议；另外看到自己已执行批次的新结果 | 测量新数值反馈的贡献 |

金融压力规则涵盖近到期、平值及参数边界等区域。具体区域、顺序和参数边界保存在 `benchmarks.py`，随源代码哈希锁定，不能观察新模型的结果后再调整。

LLM 选择的是三维矩形区域，区域内的点由 Python 生成。它不是直接输出价格，也不是自行评价自己的提议。因此这里测试的是“LLM 区域选择 + 数值采样”的组合方法。

**DE 的配置先开发、后锁定。** 在旧 `runs/demo` 模型上比较种群大小 `16、32、64`，使用开发搜索种子 `801、802、803`，在相同 1,024 点预算下按三次最大价格误差的均值选配置；相同时选更小种群。选定后才在新的三个模型上评估。初始点、DE 初始化、重复评估及实际目标函数调用都必须计入预算，不能给某个方法隐含的额外查询。

## 4. 怎样公平地比较两个 LLM 条件

两个条件必须使用同一个明确的模型 ID、相同的输出 schema、初始结果、决策次数与行动范围。协议和提示词在新模型比较前固定。每个条件共九组实验，每组七次后续决策，因此完整矩阵计划包含 **126 次 LLM 决策**。

无反馈组仍然可以看到自己此前选过哪些区域，但不得看到这些区域的新误差、最大错误点、累计指标或任何其他新数值结果。反馈组仅看到自己查询所得的结果；不得看到其他方法的结果或独立诊断集。

控制器保存每次输入、原始输出、解析后的 JSON、执行结果、模型 ID、CLI 版本、时间、预算和可观测的 token 信息。拿不到的 token 数或调用费用应标记为未知，不能估算后当作实测值。

如果调用失败或返回无效参数，控制器保存失败并停止，未完成的会话明确标出；再次运行也不会自动重试已有的失败会话。不能用手动助手回答补齐、悄悄删除失败运行，或只选择成功运行展示。若另行研究重试策略，需新建协议，并把实际调用数与计划决策数分开统计。

工作目录、只读沙箱和精简上下文有助于减少无关信息，但不能自动保证模型完全无法读取本机其他路径。结论应描述实际施加的访问限制；如审计发现读取隐藏结果，应将该运行标为受污染并按公开规则处理。

## 5. 预先确定的指标

令价格误差为 `e=abs(C_pred-C_BS)/K`。最大误差越大，意味着测试方法发现的问题越严重；它不表示神经网络变得更好。

| 指标 | 用途与解释 |
|---|---|
| **1,024 点后找到的最大绝对价格误差** | 主要指标；同时报告归一化误差及 `K=100` 的价格单位 |
| 最佳已发现误差随累计评估点数的曲线 | 比较问题发现的速度 |
| 超过阈值的固定参数网格数 | 覆盖度；使用既有 `6×5×4=120` 个网格 |
| 价格上下界违反情况 | 检查定价输出的基本约束 |
| 无效提议、未完成会话、总运行时间、调用数 | 可靠性与使用成本 |
| 独立诊断集上的价格与 delta 误差 | 描述被测试网络的缺陷，不作为搜索反馈 |

失败阈值提前固定为 `e>0.001`，即 `K=100` 时价格误差大于 0.10。它是本项目的研究约定，不是行业标准。失败网格只表示参数空间覆盖，不代表不同的错误机制；也不能用它推断错误在真实市场中的发生频率。

计算成本与 LLM 等待时间分别报告，再给出端到端耗时。数值查询预算相同不代表总成本相同。在这种便宜的三维定价公式上，LLM 很可能付出更高的时间成本，即使它能更快找到极端错误。

## 6. Delta：有金融意义的独立诊断

对无分红 Black–Scholes 看涨期权，解析 delta 为 `Phi(d1)`。若网络学习 `f(m,T,sigma)=C/K`，因为 `m=S/K`，所以在固定 `K` 下：

`dC/dS = K × df/dm × (1/K) = df/dm`。

自动微分必须包含输入归一化的链式法则，不能直接把对归一化输入的导数当作 delta。独立检查解析 delta、有限差分及网络导数的单位和实现。

本轮仍然只用**价格误差**指导搜索。Delta 是在独立测试集和压力诊断集上事后报告的次要指标；提前规定绝对 delta 误差大于 `0.05` 为诊断标记，并报告完整的连续误差指标，不再根据 delta 结果修改提示词或目标函数。该阈值同样是研究约定。这样可以研究“价格近似较好是否仍会伴随不可靠的敏感度”，但不把它夸大成已实现的对冲损益改进。

## 7. 分析和停止规则

先按相同模型、相同搜索种子计算配对差异，再列出每个模型的结果、全部九组结果、平均值/中位数及胜负情况。九组设置共享三个网络，**不是九个独立模型样本**；只有三个训练实例，不宜给出很强的总体显著性或普遍优越性结论。

主要比较是反馈与无反馈的配对差异；其他方法回答额外的实用价值问题。不要在看完结果后改成表现最好的一项 KPI。不要只展示最有利的网络或搜索种子。

配置、代码版本、数据与 checkpoint 哈希以及时间戳应随研究保存。这里的“预先锁定”是本地可审计记录，**不是公开注册的研究**。允许在开发样例上修正程序错误；正式运行若发现影响结论的 bug，应记录原因，版本化修复，并重新执行受影响的整套比较。

## 8. 运行顺序与完成标准

在仓库根目录运行。若下载包已包含 `studies/erdos_v2` 的数值结果，跳过第一条 `prepare`；程序拒绝覆盖已有研究。想从头复现时，将三条命令中的研究目录统一改成一个新名字，例如 `studies/erdos_v2_reproduce`：

```bash
python scripts/run_study.py --phase prepare --study studies/erdos_v2
python scripts/run_study.py --phase agents --study studies/erdos_v2 --model MODEL_ID
python scripts/run_study.py --phase report --study studies/erdos_v2
```

`prepare` 准备并锁定实验，训练新模型，运行数值基线及独立诊断。`agents` 需要本机可用且已登录的 Codex CLI，以及账号实际可用的明确模型 ID。`report` 按已有真实结果生成报告，并区分完成、失败和待执行的会话。

交付环境没有可用的已登录 Codex CLI，因此不得声称 LLM 矩阵已完成。数值部分的实际结果应从研究报告读取；LLM 条件在真正执行前保持待完成。旧的手动 pilot 不替代新研究的任一条件。

首版完成标准是：所有数值方法按预算运行；参考定价、梯度与预算测试通过；两个 LLM 条件实际运行并保留完整日志；报告所有结果及局限。之后再决定是否扩大样本，不把 Heston、强化学习、多 agent 或实时新闻系统加入当前范围。

## 9. Erdos 第一次 check-in 可使用的内容

**Project description（范围）：** 本项目训练小型神经网络近似欧式看涨期权的 Black–Scholes 价格，再研究 LLM agent 能否利用数值反馈改善模型测试。我们在冻结的多个模型上，以统一查询预算比较反馈与无反馈 LLM、随机和 Sobol 采样、固定金融压力测试以及差分进化。主要评价发现定价错误的能力，并独立检查 delta 敏感度。项目不以预测资产涨跌或获得交易盈利为目标。

**Dataset description（数据）：** 主数据为可复现的合成参数和 Black–Scholes 价格；每个模型实例有 32,768/4,096/8,192/8,192 条训练、验证、测试、压力诊断样本。参考计算器以 [QuantLib 公开欧洲期权测试](https://github.com/lballabio/QuantLib/blob/aaed737ba0d11a95b1df4c97c256c500275884df/test-suite/europeanoption.cpp) 中的 22 条看涨样例交叉核对。详细来源见 [DATA_SOURCES.md](DATA_SOURCES.md)。

**Stakeholders（相关者）：** 项目成员与 Erdos 导师需要判断实验是否可信、下一步是否值得投入；假设中的模型验证团队关心测试覆盖和错误发现成本；定价模型开发者关心错误集中在哪些参数区域。后两类是潜在使用者，不是已经参与或认可项目的实际机构。

**KPIs（成功指标）：** 完成可复现且无预算超支的配对比较；报告固定预算下的最大定价误差、搜索曲线、失败网格覆盖、独立 delta 误差和调用成本。反馈组是否提升性能是待回答的问题，不预设必须实现某个百分比提升。

## 10. 方法动机与阅读

- [R&D-Agent-Quant](https://arxiv.org/abs/2505.15155)：参考假设、执行、评价与反馈的研究工作流，不移植其收益结论。
- [KTD-Fin](https://arxiv.org/abs/2605.28359)：提醒我们识别 agent 决策本身的贡献，避免将其他因素带来的结果归因给 LLM。
- [Pricing options and computing implied volatilities using neural networks](https://arxiv.org/abs/1901.08943)：神经定价近似的背景；我们的贡献是测试与评价设计，而不是提出新的 Black–Scholes 公式。
